# Sultan Gril House — мобильная адаптация

Версия с Tailwind CSS для адаптивной вёрстки. Десктоп остаётся пиксель-в-пиксель идентичен предыдущей версии — все исходные inline-стили (`style={{...}}`) сохранены. Tailwind подключён поверх и используется **только** для мобильных переопределений через префикс `max-md:` (применяется при ширине меньше 768px).

## Что изменилось

**Добавлены файлы:**
- `tailwind.config.js`, `postcss.config.js` — конфиги Tailwind
- `src/index.css` — Tailwind-директивы + базовые глобальные стили (перенесены из `<style>` в `index.html`)

**Изменены файлы:**
- `package.json` — добавлены `tailwindcss`, `autoprefixer`, `postcss` в devDependencies
- `index.html` — убран блок `<style>` (теперь в `index.css`)
- `src/main.jsx` — добавлен `import './index.css'`
- Все компоненты — добавлены `className="max-md:..."` поверх существующих inline-стилей

**Не изменена логика:**
- Корзина, фильтры, модалка, валидация формы — всё работает как раньше

## Установка и запуск

В корне проекта:

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`.

Для продакшен-сборки:

```bash
npm run build
```

Готовый билд будет в папке `dist/`.

## Логика адаптива

Tailwind по умолчанию работает по принципу mobile-first, но в этом проекте используется обратный подход — `max-md:` (применяется когда ширина **меньше** 768px). Это позволяет:

1. Не трогать существующие inline-стили (они продолжают работать на десктопе как раньше)
2. Использовать `!` в Tailwind-классах (`max-md:!grid-cols-1`) — модификатор `!` ставит `!important`, который перебивает inline-стили только в мобильном viewport

**Брейкпоинты:**
- базовый (без префикса) — применяется всегда
- `sm:` — от 640px
- `max-md:` — меньше 768px (мобайл)
- `sm:max-md:` — 640–767px (планшет в портрете)

## Основные точки адаптации

- **Header** — на мобилке прячется горизонтальная навигация, появляется бургер-меню с выпадающим списком. Телефон спрятан, кнопка «Корзина» сжимается до иконки + суммы
- **HeroSlider** — фото и текст ставятся в колонку, стрелки прячутся (свайп через точки), шрифты уменьшены
- **HomePage** — категории 6→2 колонок, блюда 4→1 (на sm — 2), фичи 4→1 (на sm — 2), статистика 4→2, CTA-блок ставится в колонку
- **CatalogPage** — поиск под заголовком на всю ширину, табы категорий горизонтально скроллятся, сортировка во всю ширину
- **CartPage** — двухколоночный layout (товары + форма) становится одноколоночным, элемент корзины перекомпонован (изображение+название сверху, количество+цена+удалить снизу), форма становится не-sticky
- **ProductModal** — на мобилке открывается как bottom-sheet (закреплено снизу, скругление только сверху, максимум 92% высоты экрана)
- **PromoPage** — featured-сетка 1.4fr/1fr→1, время суток 3→1, лояльность 4→2, бизнес-секция в колонку
- **DeliveryPage** — карточки доставки 2→1, способы оплаты 3→1
- **Footer** — сетка 4 колонок→1, нижний блок в колонку

## Следующий шаг — WooCommerce

Когда будем переключаться на WordPress + WooCommerce:

1. Создать файл `src/api.js` с функциями вместо импорта из `data/menu.js`:
   ```js
   export const fetchMenu = () => fetch('/wp-json/wc/v3/products')
     .then(r => r.json())
     .then(items => items.map(p => ({
       id: p.id,
       cat: p.categories[0]?.slug,
       name: p.name,
       desc: p.short_description.replace(/<[^>]+>/g, ''),
       price: parseInt(p.price),
       photo: p.images[0]?.src,
       weight: p.attributes.find(a => a.name === 'Вес')?.options[0],
       kcal: parseInt(p.attributes.find(a => a.name === 'Ккал')?.options[0] || 0),
       rating: parseFloat(p.average_rating),
       reviews: p.rating_count,
       popular: p.featured,
       badge: null,
     })));
   ```
2. В компонентах вместо `import { MENU } from '../data/menu.js'` использовать загрузку через `useEffect`+`useState`.
3. Билд кладётся в WordPress как статика, либо через шорткод в страницу.

Структура компонентов и стили адаптива при этом не трогаются.
